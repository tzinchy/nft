# NFC Control

Постоянные ссылки для NFC-меток. В метку один раз пишется `https://<домен>/t/<токен>`, сервер отправляет человека туда, куда указано в админке. Ссылку можно менять сколько угодно, метку перепрошивать не нужно. ТЗ — `docs/ТЗ.docx`.

## Запуск в Docker (локально)

```sh
docker compose up -d --build
```

Админка: http://localhost:8080/panel/ — при первом входе создаётся администратор. Кабинет клиента: http://localhost:8080/cabinet/
База лежит в volume `data` и переживает пересборку.

## Прод (VPS с Docker)

1. Купить домен, A-запись → IP сервера.
2. Залить папку на сервер (`scp -r` или `git clone`), рядом создать `.env` по образцу `.env.example`.
3. Запустить вместе с Caddy (HTTPS получит сам):
   ```sh
   docker compose --profile prod up -d --build
   ```
4. Открыть `https://<домен>/<PANEL_PATH>/`, создать администратора.

Обновление: `git pull && docker compose --profile prod up -d --build`.

Бэкап базы:
```sh
docker compose stop app
docker run --rm -v nfc-control_data:/data -v "$PWD":/backup alpine cp /data/nfc.db /backup/nfc-$(date +%F).db
docker compose start app
```

## Настройки (env, см. `.env.example`)

| Переменная            | По умолчанию               | Что это                                                  |
|-----------------------|----------------------------|----------------------------------------------------------|
| `PUBLIC_URL`          | `http://localhost:8080`    | адрес, который пишется в метки — потом не менять         |
| `PANEL_PATH`          | `/panel`                   | путь админки — в проде поставьте свой, случайный        |
| `DOMAIN`              | `localhost`                | домен для Caddy (только профиль `prod`)                  |
| `YOOKASSA_SHOP_ID`    | —                          | shopId ЮKassa; пусто — онлайн-оплата выключена           |
| `YOOKASSA_SECRET_KEY` | —                          | секретный ключ ЮKassa                                    |
| `YOOKASSA_RECEIPT`    | `0`                        | `1` — передавать чек 54-ФЗ                               |
| `TELEGRAM_BOT_TOKEN`  | —                          | токен бота от @BotFather; пусто — уведомления выключены |
| `HTTPS_PROXY`         | —                          | прокси для api.telegram.org (`socks5://…`, `http://…`)   |
| `TELEGRAM_API`        | `https://api.telegram.org` | свой Bot API сервер вместо официального                  |

## Кабинет клиента

Админка → предприятие → «Дать доступ клиенту» (почта + временный пароль). Клиент входит на `https://<домен>/cabinet/`:
видит свои точки, метки и статистику, меняет ссылки и вкл/выкл метки (с историей и откатом), оплачивает продление,
привязывает Telegram, меняет пароль. Создавать точки и метки может только админ. Чужие предприятия клиенту недоступны.

## Оплата (ЮKassa)

1. Зарегистрироваться на yookassa.ru (для проверки есть тестовый магазин — договор не нужен).
2. Интеграция → Ключи API: взять shopId и секретный ключ → в `.env`.
3. Интеграция → HTTP-уведомления: URL `https://<домен>/pay/yookassa`, событие `payment.succeeded` и `payment.canceled`.
4. Клиент жмёт «Продлить на год» в кабинете → страница оплаты ЮKassa → после оплаты подписка продлевается на 12 месяцев
   (от даты окончания, а если уже истекла — от сегодня). Статус платежа всегда перепроверяется запросом к API ЮKassa.

Наличные/перевод: в админке «Отметить оплату» — продление то же самое.
Тестовые карты ЮKassa: https://yookassa.ru/developers/payment-acceptance/testing-and-going-live/testing

## Telegram

1. @BotFather → `/newbot` → токен в `TELEGRAM_BOT_TOKEN`.
2. В админке и в кабинете кнопка «Привязать» → открывается бот → «Start» — готово.

Что приходит:
- админу: оплата пришла; раз в день (10:00 МСК) — у кого подписка истекает через 30/7/3/1/0 дней или уже истекла;
- клиенту: напоминания о продлении со ссылкой на оплату; по понедельникам — отчёт по переходам за неделю.

Сообщения копятся в очереди и отправляются с повторами — если Telegram с сервера недоступен (в РФ бывает),
ничего не теряется. Обход: `HTTPS_PROXY=socks5://...` или VPS за пределами РФ.

## Аналитика

На странице метки, предприятия и в кабинете: переходы за 7/30/90 дней, уникальные посетители, по дням, по часам (МСК),
по дням недели, устройства (iPhone/Android), топ меток. Превью ссылок в мессенджерах и поисковые роботы не считаются.
IP и браузер не хранятся — только обезличенный дневной идентификатор.

## Как записать метку

1. Админка → предприятие → точка → «Добавить метку», указать куда вести.
2. На странице метки нажать на «Адрес для записи в NFC» — скопируется.
3. Телефон с NFC + приложение **NFC Tools**: Записать → Добавить запись → URL/URI → вставить адрес → Записать → поднести метку.
4. Там же «Другое → Заблокировать метку» (необратимо), чтобы никто не перезаписал. Ссылку назначения всё равно можно менять в админке.
5. Проверить: поднести любой телефон — должен открыться нужный сайт, в админке +1 переход.

Метки: NTAG213 достаточно (адрес ~40 байт из 144). На металл — только «anti-metal» метки.
